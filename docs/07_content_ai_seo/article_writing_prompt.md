# Промпт для написания обогащённых статей PixelRing

> Этот документ — инструкция для агента, который пишет сервисные статьи.
> Структура, архитектура и SEO/GEO-требования зафиксированы.
> Тематика и конкретный контент меняются от статьи к статье.

---

## Контекст проекта

PixelRing — сервисная компания по ремонту, обслуживанию и монтажу наружной рекламы, световых вывесок, плёнок, брендинга.

- **Не** маркетплейс, **не** каталог мастеров, **не** listing-платформа.
- Одна ответственная компания. Один вход для заявки. AI помогает на входе, люди выполняют работу.
- Язык-оригинал: немецкий. MVP-языки: DE, EN, RU, TR, PL, AR.

Каждая статья существует в **трёх формах** (три «тира»):

| Форма | Где используется | Объём |
|-------|-----------------|-------|
| **Card (короткая)** | Карточка на странице `/probleme-loesungen` — заголовок + 1 предложение-симптом + 1 предложение-решение | 2–3 строки |
| **Modal (средняя)** | Модальное окно при клике на карточку — bullet-списки причин, проверок, предупреждений | 200–400 слов |
| **Full page (длинная)** | Каноническая страница `/[locale]/probleme-loesungen/[slug]` — полная экспертная статья | 3000–5000 слов |

---

## Задание

Напиши полную статью (full page) по теме: **[ТЕМА СТАТЬИ]**.

Статья должна быть написана на **[ЯЗЫК]** как носитель языка — не переводом, а оригинальным текстом. Стиль: опытный инженер по наружной рекламе объясняет проблему клиенту — профессионально, конкретно, без воды и маркетинговых клише.

## Обязательная структура full-page статьи

Статья состоит из **фиксированных секций** в строго определённом порядке. Каждая секция начинается с `## заголовка`. Подразделы используют `###`.

### Секция 1: `# [Заголовок статьи]`

Один `h1` — он же `<title>` страницы. Формат:
```
[Название проблемы]: причины, диагностика и что делать
```

### Секция 2: `## Короткий ответ`

2–4 абзаца. Это **самая важная SEO/GEO секция**:
- Первый абзац — прямой ответ на вопрос «почему это происходит» (Google Featured Snippet target).
- Второй абзац — перечисление 5–7 наиболее вероятных причин через запятую в одном предложении.
- Третий абзац — что будет, если не действовать (мотивация к обращению, без давления).
- Четвёртый абзац — как обычно решается (общий обзор, без деталей).

> **GEO-правило**: AI-поисковик часто цитирует именно первый блок. Он должен быть самодостаточным ответом.

### Секция 3: `## Что обычно означает [проблема]`

Объясни проблему с технической стороны — не причины, а **что происходит в системе**. 
Заверши секцию маркированным списком из 5–7 диагностических вопросов, по которым можно сузить область поиска.

### Секция 4: `## Диагностика по [характерному признаку]`

**ТАБЛИЦА** — обязательный элемент. Формат:

```markdown
| Как проявляется проблема | Что вероятнее всего проверять |
|---|---|
| [Симптом 1] | [Что проверять] |
| [Симптом 2] | [Что проверять] |
...
```

Требования к таблице:
- **8–12 строк** — каждая строка = один конкретный паттерн проявления проблемы.
- Левый столбец: как клиент видит/описывает проблему (бытовым языком).
- Правый столбец: что специалист проверяет (технический язык, но понятный).
- Это **ключевой SEO/GEO-актив**: Google может показать как featured snippet, AI-поисковик цитирует строки.

### Секция 5: `## Основные причины [проблемы]`

**8–10 подразделов** `### 1. Название причины`, `### 2. ...` и т.д.

Каждый подраздел — 1–3 абзаца:
- Почему это происходит (механизм).
- Как проявляется.
- К чему приводит, если не устранить.

> Не нужны инструкции по ремонту — клиент не ремонтирует сам. Нужно понимание «почему это серьёзно и почему стоит обратиться».

### Секция 6: `## Что можно безопасно проверить самостоятельно`

**7–10 пунктов** маркированным списком. Каждый пункт — одно конкретное действие или наблюдение, которое клиент может выполнить БЕЗ:
- вскрытия корпуса
- работы с электричеством
- подъёма на высоту
- использования инструментов

Завершить абзацем: «Очень полезно снять короткое видео. Два кадра: общий план и крупный план проблемного участка.»

### Секция 7: `## Чего не стоит делать`

**6–8 пунктов** маркированным списком — конкретные опасные или бесполезные действия, от которых нужно удержать клиента.

### Секция 8: `## Когда нужно действовать срочно`

Один плотный абзац с перечислением через запятую: при каких признаках нужно **немедленно** обесточить и вызвать специалиста.

### Секция 9: `## Как PixelRing обычно диагностирует проблему`

**Нумерованный список из 6–8 шагов** — что PixelRing проверяет и в каком порядке. Первые шаги — дистанционно (по фото/видео), последние — при выезде.

### Секция 10: `## Как обычно решается проблема`

Один абзац — перечисление возможных решений. Без обещаний цен и сроков.

### Секция 11: `## Что отправить PixelRing для быстрой оценки`

**Маркированный список 7–9 пунктов**: что конкретно прислать (фото, видео, описание, адрес, высота монтажа и т.д.).

### Секция 12: `## Похожие ситуации`

**Маркированный список 3–5 пунктов** — названия связанных проблем. Эти записи станут ссылками в разделе «Похожие проблемы» на сайте (cross-linking для SEO).

## Дополнительно: средняя и короткая версии

После написания full page, **извлеки** из неё данные для Card и Modal:

### Card (для `page.tsx` CONTENT)

```javascript
{
  id: '[card-id]',
  intent: '[problem-intent]',
  title: '[Заголовок, 3–5 слов]',
  symptom: '[Одно предложение — как клиент видит проблему]',
  solution: '[Одно предложение — что делает PixelRing]'
}
```

### Modal / CMS fields (для seed script)

```javascript
{
  shortAnswer: '[Первый абзац из секции "Короткий ответ" — 2–3 предложения]',
  causes: ['[причина 1]', '[причина 2]', ...],       // 8–10 строк из секции 5
  safeChecks: ['[проверка 1]', '[проверка 2]', ...],  // 7–10 строк из секции 6
  urgentWarnings: ['[сигнал 1]', '[сигнал 2]', ...],  // 3–4 строки из секции 8
  serviceProcess: ['[шаг 1]', '[шаг 2]', ...],        // 6–8 строк из секции 9
  workScopeFactors: ['[фактор 1]', '[фактор 2]', ...] // 6–8 факторов
}
```

## SEO/GEO правила для текста

1. **Не начинай абзацы с «В данной статье...», «Рассмотрим...», «Давайте разберёмся...»** — это пустые конструкции, которые AI-поисковик пропускает.

2. **Первое предложение каждой секции = самодостаточный ответ.** Если AI вырвет только первое предложение — оно должно иметь смысл.

3. **Не используй слово «мы» без указания «PixelRing».** AI-поисковик должен знать, КТО это — иначе не будет атрибуции.

4. **Таблица обязательна.** Без таблицы статья теряет 30–40% SEO/GEO потенциала.

5. **Не обещай цены, сроки, гарантии.** Только факты: что проверяем, что может быть причиной, что делать.

6. **Используй конкретные технические термины** (блок питания, LED-модуль, контроллер, IP-защита, кабельное сечение), но сразу объясняй их влияние на проблему.

7. **Пиши как инженер с 20-летним опытом**, а не как копирайтер. Никаких «уникальных решений», «индивидуального подхода», «команды профессионалов».

8. **Каждая секция — отдельный passage для Google Passage Ranking.** Секция должна быть самодостаточной: даже вырванная из контекста, она отвечает на конкретный вопрос.
