# Документы клиенту по заявке

## Текущее состояние

2026-09-29: локально реализована передача готовых PDF из служебной системы в кабинет клиента. Миграция применена к подключённой базе 2026-09-29; выпуск приложения подготавливается. Это передача документов, без создания счетов, учёта оплаты, электронной подписи и финансовых статусов.

## Сценарий сотрудника

В карточке заявки доступна вкладка «Документы клиенту». Сотрудник выбирает PDF до 4 МБ и загружает черновик. Затем выбирает тип — счёт, договор, акт выполненных работ или другой документ — указывает название и необязательный комментарий и нажимает «Отправить клиенту».

Загруженный файл сохраняется как черновик и доступен сотрудникам, имеющим доступ к заявке. Название по умолчанию берётся из имени файла. Изменённые поля применяются при отправке; несохранённые изменения полей теряются при уходе со вкладки. После отправки документ неизменяем. Исправленный документ передаётся новым PDF; отзыв или удаление отправленных документов в этот блок не входят.

Для отправки необходимы номер заявки и хотя бы один действующий доступ активного пользователя кабинета к заявке. Без этого файл остаётся черновиком, сотрудник получает пояснение. Публикация не меняет статус заявки.

## Кабинет клиента

В карточке соответствующей заявки, перед результатом ремонта, находится раздел «Документы». В нём видны только отправленные документы: тип, название, дата отправки, комментарий, кнопки открытия и скачивания. В переписку добавляется одно сообщение со ссылкой на защищённый PDF. Открытый список обновляется при возвращении в окно и каждые 30 секунд, пока страница видима.

Интерфейс документов переведён на немецкий, английский, русский, турецкий, польский и арабский. Арабский блок использует направление справа налево. Название, комментарий и содержимое файла передаются как введены сотрудником, без автоматического перевода. Сообщение формируется на языке заявки.

## Доступ и хранение

- Владелец и менеджер получают отдельное разрешение `CRM_DOCUMENT_WRITE` (загрузка и отправка документов). Менеджер работает только с доступной ему заявкой по существующим правилам назначения.
- PDF хранится приватно в текущем файловом хранилище. Общая видимость вложения для клиента остаётся выключенной: доступ выдаёт только маршрут опубликованных документов.
- Проверяются размер фактического потока загрузки, тип, расширение и начальная/конечная сигнатуры PDF. Это не антивирусная проверка и не полная проверка структуры PDF.
- Сервер повторно проверяет назначение менеджера под блокировкой заявки перед записью. Запросы изменения защищены от межсайтовой отправки и ограничены по частоте.
- Клиенту необходима действующая сессия активного аккаунта и неотозванный доступ именно к этой заявке. Номер заявки сам по себе доступа не даёт.
- Прямые адреса хранилища, данные сотрудника и внутренние поля черновика в клиентский ответ не попадают. Ответ с PDF запрещает кеширование и подмену типа содержимого; просмотр ограничен защитной политикой браузера.
- Повтор загрузки с тем же идентификатором и содержимым возвращает тот же документ. Повтор отправки не создаёт второй документ или второе сообщение.
- Загрузка, отправка и служебное скачивание записываются в журнал действий.

## Изменение базы

Миграция `20260929120000_case_documents` (таблица документов по заявке) добавляет одну таблицу, индексы, внешние ключи и ограничение четырёх типов документов. Существующие записи не переписываются. Не применять все накопленные миграции автоматически: перед включением проверить состояние базы и отдельно согласовать нужное применение.
