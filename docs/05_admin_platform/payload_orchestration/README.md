# Payload Orchestration Infrastructure (инфраструктура оркестрации Payload)

## Назначение

Эта папка содержит правила, оперативное состояние и шаблоны для отдельного агента-оркестратора пилота Payload CMS (новой системы управления публичным контентом).

Оркестратор управляет последовательностью, зависимостями, владением файлами и независимой проверкой. Он не реализует, не исправляет и не проверяет изменения лично.

## Границы

Планируется поэтапная реализация параллельной Payload CMS (новой системы управления публичным контентом), начиная с `Referenzen` (страницы примеров работ). Основной план: [payload_parallel_cms_pilot_plan.md](../payload_parallel_cms_pilot_plan.md).

Эта папка не является реализацией Payload CMS (новой системы управления публичным контентом). На момент создания инфраструктуры:

- Payload ещё не установлен и не реализован;
- `content-studio/` ещё не создан;
- публичный маршрут `Referenzen` (страницы примеров работ) не переключён;
- текущая CMS остаётся production source (рабочим источником) до отдельного подтверждённого переключения;
- код приложения, база данных, Vercel Blob (файловое хранилище Vercel) и сервер не изменены этим документационным блоком.

## Карта файлов

- [AGENTS.md](AGENTS.md) — локальный шлюз обязательных правил папки.
- [ORCHESTRATOR_RULES.md](ORCHESTRATOR_RULES.md) — полные правила будущего оркестратора.
- [ORCHESTRATOR_BOOTSTRAP_PROMPT.md](ORCHESTRATOR_BOOTSTRAP_PROMPT.md) — готовый стартовый промт для нового оркестратора.
- [PROGRESS.md](PROGRESS.md) — единственный оперативный источник состояния этой инициативы и документ восстановления после паузы.
- [TASK_PACKET_TEMPLATE.md](TASK_PACKET_TEMPLATE.md) — обязательный шаблон task packet (пакета задания).
- [WORKER_REPORT_TEMPLATE.md](WORKER_REPORT_TEMPLATE.md) — обязательный шаблон отчёта агента-исполнителя.
- [VERIFICATION_REPORT_TEMPLATE.md](VERIFICATION_REPORT_TEMPLATE.md) — обязательный шаблон отчёта независимого агента-проверяющего.

## Порядок запуска

1. Открыть [ORCHESTRATOR_BOOTSTRAP_PROMPT.md](ORCHESTRATOR_BOOTSTRAP_PROMPT.md).
2. Передать его новому агенту.
3. Агент читает корневой [AGENTS.md](../../../AGENTS.md).
4. Агент полностью читает [ORCHESTRATOR_RULES.md](ORCHESTRATOR_RULES.md).
5. Агент читает в [PROGRESS.md](PROGRESS.md) только `Context Beacon` (контекстный маяк), активную доску задач, реестр подтверждений, последние три записи и следующее действие.
6. Агент проверяет наличие подтверждения владельца на следующий шаг.
7. Только затем агент создаёт задания рабочим агентам по [TASK_PACKET_TEMPLATE.md](TASK_PACKET_TEMPLATE.md).

После паузы или компрессии контекста восстановление всегда начинается с [PROGRESS.md](PROGRESS.md), а не с перечитывания репозитория или всей истории.
