## Current Architecture Decision (текущее архитектурное решение)

- Владелец выбрал Payload после сравнения со Strapi.
- Основной план: [`../payload_parallel_cms_pilot_plan.md`](../payload_parallel_cms_pilot_plan.md).
- Новое приложение планируется в изолированном `content-studio/`, но папка ещё не создана.
- Первый пилотный объект — `Referenzen` (страница примеров работ).
- Текущая CMS остаётся единственным production source (рабочим источником) до отдельного переключения.
- Production-база (рабочая база) этой инициативой не изменялась.
- Vercel Blob (файловое хранилище Vercel) этой инициативой не изменялся.
- Миграции Payload не создавались и не применялись.
- Deployment (размещение) не выполнялся.
- Экспорт старой CMS должен быть read-only (только для чтения); импорт использует копии, без dual write (двусторонней записи).
- Существующие `CmsPage`, `CmsMedia` и Blob-файлы не удаляются в рамках пилота.
- CRM (система работы с заявками), AI Knowledge (управление знаниями для ИИ), клиентский кабинет и операционные модули не переносятся этим пилотом.

## Open Risks And Blockers (открытые риски и блокеры)

- В рабочем дереве есть незакоммиченные изменения предыдущего усиления `Referenzen` (страницы примеров работ). Они принадлежат владельцу и не должны быть перезаписаны, отформатированы или откачены.
- Шаг 1 заблокирован до отдельного подтверждения владельца.
- Две CMS не могут одновременно быть редактируемыми источниками одной страницы.
- Production-база (рабочая база) и production Blob (рабочее файловое хранилище) не предназначены для локальной разработки.
- Любые миграции, удаление, server write (запись на сервер), deployment (размещение) и переключение источника имеют отдельные approval gates (ворота подтверждения).
