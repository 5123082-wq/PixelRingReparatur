# Аудит мёртвого кода и остатков удалённых функций — 2026-07-14

## Назначение документа

Этот документ фиксирует полный аудит текущего рабочего дерева PixelRing Reparatur и служит основой для последующей пошаговой очистки.

Аудит выполнен без изменений приложения, конфигурации и данных. Найденные элементы не являются разрешением на автоматическое удаление: каждый блок очистки должен отдельно пройти правило `прочитать → объяснить → предложить действие → получить подтверждение → изменить → проверить`.

Область аудита:

- приложение `signage-service/`;
- TypeScript/React-код;
- маршруты Next.js (файловые маршруты приложения);
- локализации DE/EN/RU/TR/PL/AR;
- CMS (система управления контентом), Prisma и скрипты заполнения базы;
- CSS и Tailwind CSS (система утилитарных стилей);
- `public/` и медиаресурсы;
- тесты, диагностические и миграционные скрипты;
- история Git для подтверждения снятых с рендера функций.

Снимок состояния: 2026-07-14. Рабочее дерево на момент аудита уже содержало изменения владельца; аудит рассматривал именно это состояние и не изменял его.

## Краткий итог

Один случай в сводке означает один связный комплект кода, данных и ресурсов, а не каждую отдельную строку.

- 8 наборов подтверждённого мёртвого кода.
- 5 наборов вероятно мёртвого кода.
- 15 цепочек — остатки удалённых функций.
- 7 случаев требуют решения владельца.
- 8 осиротевших UI-компонентов (компонентов интерфейса): 1 706 строк.
- 1 182 неиспользуемых локализованных значения; ещё 18 значений требуют миграции. Всего 1 200 невыводимых значений.
- Около 4 700 строк кода и JSON относятся к подтверждённым остаткам; ещё 692 строки — вероятные одноразовые скрипты.
- Потенциально можно полностью удалить до 58 файлов: 11 файлов кода/тестов, 13 вероятных диагностических скриптов и 34 ресурса.
- 34 вероятно удаляемых ресурса занимают около 24,3 MiB. Ещё 4 файла на 7,9 MiB требуют решения владельца.
- В `public/` найдено 38 кандидатов на 32,26 MiB после исключения динамически формируемых путей.
- Устаревшие поля или блоки присутствуют в 30 опубликованных CMS-страницах (страницах системы управления контентом) и 291 исторической ревизии. Историю ревизий автоматически удалять нельзя.

TypeScript (проверка типов) на момент аудита содержит два отдельных сбоя:

1. Лишний экспорт в `/[locale]/referenzen` (локализованной странице примеров работ) — относится к этому аудиту.
2. Несовместимый тип `searchParams` (параметров URL) на странице статуса — прежняя несвязанная ошибка.

Ограничения:

- логи обращений к production (рабочему сайту) недоступны;
- ручные внешние вызовы диагностических скриптов и внутренних API (программных интерфейсов) нельзя полностью исключить;
- прямые старые URL (адреса) ресурсов нельзя признать неиспользуемыми без журналов обращений;
- тесты, способные изменить реальную базу, не запускались.

## Классификация

- `C` — подтверждённый мёртвый код.
- `R` — остаток удалённой функции.
- `P` — вероятно мёртвый код.
- `O` — требуется решение владельца.

Приоритеты:

- `P0` — сначала устранить функциональный или сборочный риск.
- `P1` — высокий эффект или крупная подтверждённая цепочка.
- `P2` — полезная плановая очистка.
- `P3` — низкорисковая косметическая очистка.

### O4 — сужение CRM API

Текущий detail UI (интерфейс деталей заявки) не читает часть полей контакта, дат, AI-паузы, диалогов, сессий, событий статуса и вложений. Список CRM также не читает часть временных полей, `_count` и часть последнего сообщения.

Безопасная последовательность:

1. Удалить только локальные неиспользуемые поля типов.
2. Проверить скрипты и возможные внутренние потребители API.
3. Отдельно сузить Prisma `select` и JSON-ответ.
4. Запустить административные runtime/e2e tests (рабочие и сквозные тесты).

### O5 — отклонённые визуалы и runtime storage (хранилище времени выполнения)

### O6 — старый административный псевдоним

`src/proxy.ts:77-82` перенаправляет `/ring-master-admin*` на `/ring-manager-crm*`. Это технически действующий alias (псевдоним), а не мёртвый маршрут.

Удаление возможно после проверки:

- журналов обращений;
- закладок владельца/менеджеров;
- внутренних операционных инструкций.

### O7 — политика резервных переводов

- Страница `/[locale]/leistungen/beleuchtete-markisenvolants` (локализованная страница световых маркизных воланов) имеет RU и DE, а EN/TR/PL/AR получают немецкий резервный текст. Маршрут пока закрыт `noindex/no-follow` (запретом индексации).
- `Header` (шапка сайта) содержит шестиязычную резервную карту, хотя ключи гарантированно существуют в JSON.
- `StatusLookup` (форма проверки статуса) содержит 24 резервные строки для четырёх `chat_gate_*` ключей.

Решение: либо один источник переводов, либо явно документированный резервный слой с тестом отсутствующих ключей.
